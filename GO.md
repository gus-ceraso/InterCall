# InterCall Go Proof of Concept — Usage

This document is the usage guide for the Go proof of concept: the
`intercall-go` command, the generated import and export bindings, and the
`intercall` runtime. It is a user-facing companion to the normative
documents:

- [`README.md`](README.md) defines the InterCall interface language and wire
  protocol.
- [`SPEC.md`](SPEC.md) defines the Go mapping, generator, CLI, and runtime
  architecture.
- This file shows how to build the CLI, generate both binding directions
  from real Go code and interface files, and construct, bind, call, close,
  and wait on a connection.

## Requirements and build

The module `github.com/cerasos/intercall` declares Go 1.26.5. Build the CLI
from the module root:

```sh
go build -o intercall-go ./cmd/intercall-go
```

The runtime package and the interface syntax parser use only the standard
library. The generator's only third-party dependency is the pinned
`golang.org/x/tools/go/packages` loader. Generated bindings import the
standard library, the root runtime, and — for export — the provider
packages; they never import generator internals.

## The two binding directions

A peer that *accepts* calls exports an interface; a peer that *makes* calls
imports that interface. The two directions produce two separate generated
packages:

| Direction | Input | Command | Output |
| --- | --- | --- | --- |
| Export | Tagged Go provider packages | `intercall-go export` | One export binding plus its owned interface file |
| Import | One exact `.intercall` file | `intercall-go import` | One import binding with typed callers |

The interface file is the shared contract: export writes it from tagged Go
code, and import reads it to generate callers. Import accepts any
protocol-valid interface file; it does not have to come from this tool.

## Quick start

This walkthrough generates both directions of one small `hello` service and
then runs a call over an in-memory byte stream. The steps are the same with
any transport.

### 1. Write the provider package

An export provider is an exported, nongeneric, nonvariadic package-level
function whose first parameter is exactly `context.Context` and whose last
result is the predeclared `error`:

```go
// Package hello exports one InterCall procedure.
package hello

import "context"

// Hello returns a greeting for name.
// @intercall procedure hello
// @param name The name to greet.
// @return The greeting.
func Hello(ctx context.Context, name string) (string, error) {
	return "hello, " + name, nil
}
```

The `@intercall procedure` directive marks the function as selectable.
Directives occupy complete lines of the Go doc comment. Reachable value
types are named with `@intercall type` on the defined type, and application
exceptions with `@intercall exception` on an exported `error` variable or on
an exported struct type whose pointer implements `error`. `@intercall param`
names a wire parameter, `@param` supplies its documentation, and `@return`
documents the return value. Methods, generics, variadics, and any signature
other than the two forms above are rejected. The context parameter and the
final `error` result are never wire values.

### 2. Generate the export binding

```sh
./intercall-go export --out gen/helloserver --interface gen/hello.intercall ./hello
```

`export` requires at least one package pattern and distinct `--out` and
`--interface` targets. The command discovers the tagged procedures of the
explicit packages in the active module or workspace, validates everything in
memory, and then writes:

- `gen/helloserver/binding_gen.go` — the export binding, package
  `helloserver`, exposing `ExportBinding() intercall.ExportBinding`; and
- `gen/hello.intercall` — the owned interface file, a canonical rendering
  of the exported contract, stamped with the SHA-256 digest of its body.

Every exported interface additionally contains the three fixed no-payload
runtime exceptions `procedure_not_found`, `invalid_arguments`, and
`internal_exception`:

```text
/* Code generated by intercall-go; artifact sha256:cf123289caa70b7d11a727e07e96cc4de5bde0d0ffbf5acacb9b22903f7f85c9; DO NOT EDIT. */

exception internal_exception;

exception invalid_arguments;

exception procedure_not_found;

/* Hello returns a greeting for name. */
procedure hello {
    /* The name to greet. */
    name string;
}
/* The greeting. */
string;
```

### 3. Generate the import binding

```sh
./intercall-go import --out gen/helloclient gen/hello.intercall
```

`import` takes exactly one interface file and reads its exact bytes; stdin
is not supported. The generated `gen/helloclient/binding_gen.go` exposes the
immutable `ImportBinding() intercall.ImportBinding` singleton and one typed
caller per procedure:

```go
func Hello(ctx context.Context, name string) (string, error)
```

The caller looks the connection up in the context, encodes the request
statically, and returns the decoded return value, a decoded application
exception, or a runtime sentinel.

### 4. Construct, bind, call, close, and wait

The runtime does not dial or listen. The application supplies an established
`intercall.ByteStream` — an `io.Reader`, `io.Writer`, and `io.Closer` in one
interface — that allows one read and one write concurrently, makes `Close`
unblock both, delivers bytes reliably and in order, and begins at the first
InterCall frame. EOF and either half-close terminate the whole connection.
One duplex stream joins the two peers; both ends may share the same binding
singletons, and any number of connections may share a binding concurrently:

```go
package main

import (
	"context"
	"fmt"
	"log"

	"github.com/cerasos/intercall"

	"example.com/hello/gen/helloclient"
	"example.com/hello/gen/helloserver"
)

// connect returns the two ends of one established byte stream. Replace
// this with your transport: a pair of sockets, two pipe ends, or any
// other ByteStream.
func connect() (serverSide, clientSide intercall.ByteStream) { panic("transport") }

func main() {
	serverSide, clientSide := connect()

	// NewConnection validates its arguments before taking ownership of
	// the stream and starts both ends' receive loops before returning.
	server, err := intercall.NewConnection(context.Background(), serverSide,
		helloserver.ExportBinding(), helloclient.ImportBinding())
	if err != nil {
		log.Fatal(err)
	}
	client, err := intercall.NewConnection(context.Background(), clientSide,
		helloserver.ExportBinding(), helloclient.ImportBinding())
	if err != nil {
		log.Fatal(err)
	}

	// Generated callers retrieve the connection from the context;
	// WithConnection binds it.
	ctx := intercall.WithConnection(context.Background(), client)
	greeting, err := helloclient.Hello(ctx, "world")
	if err != nil {
		log.Fatal(err)
	}
	fmt.Println(greeting) // hello, world

	// Close terminates the connection and returns immediately; Wait
	// blocks until teardown completes and returns the permanent
	// terminal cause, which is never nil. The closed end reports
	// ErrClosed; the peer observes the connection going away as EOF on
	// its stream and terminates with that cause.
	_ = client.Close()
	fmt.Println(client.Wait()) // intercall: connection closed
	fmt.Println(server.Wait()) // intercall: read frame header: EOF
}
```

`ConnectionFromContext` returns `ErrNoConnection` when the context carries
no binding. A generated caller on a context without a connection returns
that sentinel without touching the wire.

## Command reference

```text
intercall-go export --out DIR --interface FILE [--package NAME]
    [--include full/import/path.Symbol]...
    [--exclude full/import/path.Symbol]...
    PACKAGE_PATTERN...

intercall-go import --out DIR [--package NAME]
    [--go-name SELECTOR=GoIdentifier]...
    INTERFACE_FILE
```

| Option | Meaning |
| --- | --- |
| `--out DIR` | Generated artifact directory; created if needed. |
| `--interface FILE` | Owned interface target of an export binding (export only). |
| `--package NAME` | Generated package name; defaults to an existing owned binding's package clause or to the output directory's base name. Must match `[A-Za-z_][A-Za-z0-9_]*` and not be `_`, `main`, or a Go keyword; never sanitized. |
| `--include PATH.SYM` | Restrict export selection to the named eligible function; repeatable. |
| `--exclude PATH.SYM` | Remove the named eligible function from the selection; repeatable; wins over `--include`. |
| `--go-name SEL=ID` | Override one generated Go identifier without changing wire names (import only); repeatable. |
| `--help`, `-h` | Print the help text. |

`--include` and `--exclude` selectors are exact `full/import/path.Symbol`
names of eligible functions in explicit packages. `--go-name` selectors use
exact wire names, e.g. `procedure:hello/param:name=Name` or
`type:user_id=UserID`. Diagnostics render as `path:line:column: message`
with physical byte positions; the exit status is 0 on success and 1 on any
error.

## Artifact ownership

Every binding is one file named `binding_gen.go`, whose first two lines are
exactly:

```go
// Code generated by intercall-go; DO NOT EDIT.
// intercall-go binding: import sha256:<artifact-id>
```

The second line says `export` for an export binding. The `<artifact-id>` is
the lowercase 64-hex-digit SHA-256 digest of the canonical interface body —
a local update stamp, not a runtime identity. The exported interface starts
with a matching ownership marker followed by one blank line and the
canonical body.

Validation finishes before the output directory is created, ownership checks
finish before any target is created or replaced, and owned targets are
replaced by rename rather than truncated. The tool never deletes a path and
never overwrites a handwritten or differently generated file. For identical
semantic inputs, generated bytes are identical: no timestamps, absolute
paths, or map-order-dependent data. Generated artifacts are intended to be
checked into version control, and regeneration over an unchanged interface
is a no-op.

## Runtime reference

The root package exports the generated-code bridge, the connection
lifecycle, the context binding functions, and fixed error sentinels:

| Symbol | Purpose |
| --- | --- |
| `type ByteStream` | The transport boundary: `io.Reader` + `io.Writer` + `io.Closer`. |
| `type Dispatch` | Export-side procedure dispatch: context, procedure key, request payload → exception key and response payload. |
| `type RequestEncoder` | Import-side request encoder closure, invoked at most once per call. |
| `type ResponseDecoder` | Import-side response decoder closure, invoked with the matched exception key and payload. |
| `type ExportBinding` / `type ImportBinding` | Opaque immutable binding handles; the zero value is invalid. |
| `NewExportBinding(Dispatch)` / `NewImportBinding()` | Construct the two binding handles; `NewExportBinding` rejects a nil dispatch with `ErrInvalidArgument`. |
| `NewConnection(ctx, stream, export, imp)` | Validate and construct a connection, taking ownership of the stream and starting its receive loop. |
| `(*Connection).Call(ctx, imp, key, encode, decode)` | Place one outgoing request and wait for its single outcome (generated-code SPI). |
| `(*Connection).Close()` / `(*Connection).Wait()` | Terminate without waiting; block for the permanent terminal cause, which is never nil. |
| `WithConnection(ctx, conn)` / `ConnectionFromContext(ctx)` | Bind a connection into a context under a private key and retrieve it; the nil cases follow the documented panic and sentinel contracts. |

Error sentinels work with direct comparison and `errors.Is`:
`ErrInvalidArgument`, `ErrNoConnection`, `ErrBindingMismatch`, `ErrClosed`,
`ErrRequestIDsExhausted`, and `ErrProtocol`; plus the three fixed wire
exceptions `ErrProcedureNotFound`, `ErrInvalidArguments`, and
`ErrInternalException`. The fixed exceptions' `Error` strings are their
exact wire names. A per-call context cancellation returns that context's
exact `context.Canceled` or `context.DeadlineExceeded` without terminating
the connection; a terminal event returns its exact cause.

## Out of scope

The proof of concept implements every nondeferred feature of `SPEC.md`. It
does not include TypeScript or other non-Go bindings, WebSocket or
WebTransport adapters, dialing or listening, TLS, handshakes or runtime
interface digests, authentication or authorization policy, resource limits,
transport-level cancellation, or streaming values. The interface language,
value encodings, and frame format are defined by `README.md`.
